# scripts/spec-drift-deferred.txt
#
# Scenarios (and, where noted, whole requirements) deferred from the drift
# check. The companion script scripts/check-spec-drift.mjs exempts these
# until they land literal-name coverage in typescript/packages/,
# compliance/cli/, or the compliance/vectors/ corpus. The file is auditable
# and grep-able; an entry citing a requirement or scenario that no longer
# exists in any openspec/specs/<cap>/spec.md is itself a drift failure.
#
# Lines starting with `#` are comments. Blank lines are ignored. Each
# remaining line is one of:
#   Requirement title
#   Requirement title :: Scenario title
# The first form defers every scenario under the requirement (use for
# requirements with no coverage at all, or out-of-scope wholesale). The
# second defers just that one scenario — use when a sibling scenario under
# the same requirement IS covered.
#
# Reduction discipline: when a PR adds a test that covers a deferred
# requirement or scenario, REMOVE the corresponding line in the same PR.
#
# "Covered under a different name" entries: the checker's match is a literal
# substring of the scenario title in test source (see check-spec-drift.mjs
# header) — a deliberately loose, mechanical gate, not semantic review. A
# large share of the entries below are scenarios that ARE exercised by an
# existing test, just not under the scenario's literal wording (this
# repo's tests predate the scenario-level convention this file now follows).
# Each such line names the covering test so a future rename-only PR can
# close it without re-deriving the mapping. Renaming ~50 existing tests is
# out of scope for the PR that introduced scenario-level matching (issue
# #133) — it touches every package, not scripts/ — so it's tracked here
# instead of attempted inline.
#
# Out-of-scope categories for the v0.1.0 TS receiver track:
#   - sender / outbox / retry / fanout / replay / endpoint state machine
#   - storage adapters and host-transaction passthrough
#   - multi-tenancy, observability, filtering
#   - compliance suite internals (Track A owns the runner)
#   - distribution lifecycle policies (SemVer, deprecation, migrations)
#   - api-surface-typescript surface beyond the v0.1.0 receiver-side shape
#
# Per `openspec/specs/compliance/spec.md` v0.1.0 scope, the in-scope set
# is ~17 receiver / key-management / standard-webhooks-compliance items.
# Everything else is listed below.
